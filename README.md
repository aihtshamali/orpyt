## Install

**Requirements:** macOS 13 Ventura or later.

1. Go to [**Releases**](https://github.com/aihtshamali/orpyt/releases) and download the latest `Orpyt.pkg`.
2. Open the package in macOS Installer.
3. Follow the standard install steps. Orpyt is installed directly into **Applications**.
4. Open **Applications → Orpyt**.
5. macOS will ask for confirmation the first time — click **Open**.
6. The Orpyt clock appears in your menu bar immediately.

> Orpyt is intended to ship as a signed and notarized native macOS installer package.

To enable **Launch at Login**, open Orpyt → click the settings icon → General → toggle Launch at Login.

## Features

- Dual clocks directly in the macOS menu bar
- Configurable primary and secondary time zones
- Show one clock or both
- Quick search from the popover to swap cities fast
- Current time zone shortcut from the popover and settings
- Optional 24-hour format
- Optional seconds, weekday, date, timezone abbreviation, and GMT offset
- Custom labels for each clock
- Native launch at login toggle
- Ambient or weather-based icon mode
- Live weather with graceful fallback
- Time scroller with slider and trackpad / mouse wheel scrubbing
- Optional read-only next meeting card in the popover
- Native settings window
- Smooth, animated overview cards

- `release.sh` — release archive, DMG, and notarization-ready builder

## Performance

Orpyt is designed to stay out of the way when it is not being used.

- Idle CPU usage measured at `0.0%` to `0.1%`
- Activity Monitor power field measured at `0.0` during idle sampling
- Resident memory measured at roughly `56 MB` to `99 MB`, depending on the metric used
- Thread count measured at `4`

### Live Sample Notes

- Sampled from a running menu bar instance of Orpyt on Apple silicon
- Battery sample was taken while the Mac was reporting `99%` battery and `discharging`
- The app was idle in the menu bar during measurement, not under synthetic stress

### What This Means

In normal idle use, Orpyt has negligible CPU activity and negligible energy impact. It is intended to run continuously in the menu bar without materially affecting overall system performance or battery life.

### Measurement Notes

- `ps` reported about `56.5 MB` RSS
- `vmmap` reported a `98.7 MB` physical footprint and `279.4 MB` peak footprint
- Exact per-process watt or mW battery draw requires `powermetrics` with superuser access, so the practical energy reading here is macOS `top` / Activity Monitor power impact

## Run

Clone the repo, then build and launch the distributable `.app` bundle:

```bash
git clone git@github.com:aihtshamali/orpyt.git
cd Orpyt
./build-app.sh
open dist/Orpyt.app
```

After building, you can drag `dist/Orpyt.app` into `Applications` and run it like a normal macOS app.

## Release for Users

For public distribution on macOS, build a signed release from Xcode and package it as a native macOS installer:

```bash
cd Orpyt
./release.sh
```

Release artifacts are written to:

- `dist/release/Orpyt.app`
- `dist/release/Orpyt.pkg`
- `dist/release/Orpyt.zip`
- `dist/release/Orpyt.dmg` (optional)

### Recommended Distribution Path

- Sign with `Developer ID Application`
- Sign the installer with `Developer ID Installer`
- Notarize with Apple
- Share the generated `dist/release/Orpyt.pkg`

### Local Smoke Test Without Signing

If you only want to verify the release pipeline locally:

```bash
cd Orpyt
ORPYT_ALLOW_UNSIGNED=1 ./release.sh
```

If you want to skip DMG creation and only produce the native installer package:

```bash
cd Orpyt
ORPYT_SKIP_DMG=1 ./release.sh
```

### Notarization

Use either a saved keychain profile:

```bash
ORPYT_NOTARY_PROFILE="your-notary-profile" ./release.sh
```

Or pass Apple credentials directly:

```bash
ORPYT_NOTARY_APPLE_ID="you@example.com" \
ORPYT_NOTARY_TEAM_ID="TEAMID1234" \
ORPYT_NOTARY_PASSWORD="app-specific-password" \
./release.sh
```

If notarization credentials are not provided, Orpyt still produces the release `.app`, `.pkg`, `.zip`, and `.dmg`, but skips notarization.

### App Store vs Direct Download

For direct user installs, use the PKG flow above.

If you plan to ship through the Mac App Store, use Xcode archive validation and App Store Connect instead of DMG notarization.
